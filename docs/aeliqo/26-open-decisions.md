# 26 — Defaults, unknowns, and decision triggers

## Fixed unless the user explicitly changes direction

Own ready-made components; 2D D3/no Three.js initially; core agnostic/React-first; three composition levels and separate control modes; one semantic dispatcher; app-owned business state; useful OSS; local-only project skills; continue PoC instead of blind rewrite; no fabricated benchmark/current pricing/tool success.

## Requires local audit

Actual repo/package names and versions; existing schema strategy/store/registry; PoC component inventory; current docs stack; real MCP browser-link implementation; licenses; test/CI commands; baseline hardware. Use observed code and record decision. Unknown is not permission to invent a path or install a replacement framework.

## Design defaults with change triggers

JSON Schema 2020-12 reference authoring and generated validation/types: retain a compatible existing source schema approach when it can generate the required contracts without semantic loss. SVG default: add Canvas only after equivalent-workload evidence. Ark/Zag behavior candidate: keep a healthy existing accessible foundation. Static-first docs candidate: preserve an existing capable documentation site. Serialized workspace transaction owner: add collaboration machinery only when actual multi-user requirements exceed it.

## Research/market unknowns

External-harness routing reliability; willingness to add semantic descriptors; API learnability; real overhead versus baseline; paid premium need; support burden and pricing; name/package availability. These require tests/interviews, not stronger wording in AGENTS.md.

## Decision log format

Date/context → options actually considered → decision → constraints/tradeoffs → affected contracts/files → evidence → revisit trigger. A decision isn't improved by repeatedly reopening it without new evidence. Never fork the architecture silently in a skill or example; update the canonical decision once.
