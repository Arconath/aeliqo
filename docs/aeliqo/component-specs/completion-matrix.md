# Implemented component evidence matrix

This inventory counts twenty catalog components plus the Workspace composition surface. All twenty have direct props, semantic bindings, and package subpaths backed by the same renderers. It is not a claim that every proposed component wave or every state has independent usability certification. Source APIs are authoritative; source manifests retain a private publication guard while the explicit Apache-2.0 release build emits public 0.x artifacts.

## Reproduce the evidence

Run `pnpm test` for current component/core assertions, `pnpm test:browser` for integrated workflows, and `pnpm check:packages` for tarball installation, declarations, SSR/runtime consumers, and the standalone Metric bundle graph. The documentation preview/source view shares the compiled `documentation-examples.tsx` module. Browser documentation checks cover 360/768/1280-pixel layout and keyboard-operated timeline range/event controls. The same browser suite passes in Chromium, Firefox, and WebKit; Chromium-only CDP tracing remains the source of layout/paint/heap metrics.

The package graph assertion applies specifically to standalone Metric: it must retain no D3, protocol/provider, or Workspace implementation. Trend uses D3 intentionally. Adapter imports are checked without starting a server or calling a provider. Tests are local fixture evidence, not independent usability research or a full Next.js compatibility build.

## Remaining evidence gates

The existing catalog does not receive blanket screen-reader, every-state, or usability certification from one shared test. Independent onboarding, manual screen-reader review, fresh compatible-native-WebMCP observation, real-provider BYOK proof, commercial pilots and publication approval remain separately recorded gates.
