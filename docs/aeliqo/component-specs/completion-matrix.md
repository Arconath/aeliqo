# Implemented component evidence matrix

This inventory counts sixteen catalog components plus the Workspace composition surface. Eleven have direct props and subpaths. It is not a claim that every proposed component wave or every state has independent browser certification. Source APIs are authoritative; local package versions remain private 0.x releases with license selection pending.

## Reproduce the evidence

Run `pnpm test` for current component/core assertions, `pnpm test:browser` for integrated workflows, and `pnpm check:packages` for tarball installation, declaration checks, all eleven direct-component SSR imports, and the standalone Metric bundle graph. The documentation preview/source view shares the compiled `documentation-examples.tsx` module. `Documentation.test.tsx` covers navigation, search, preview/source and actual partial-state rendering. Browser documentation checks cover 360/768/1280-pixel layout. The four additive components also have the scoped keyboard/RTL/axe scenario in `tests/additions.spec.ts`.

The package graph assertion applies specifically to standalone Metric: it must retain no D3, protocol/provider, or Workspace implementation. Trend uses D3 intentionally. Adapter imports are checked without starting a server or calling a provider. Tests are local fixture evidence, not independent usability research or a full Next.js compatibility build.

## Remaining evidence gates

Each retained semantic-only component needs a task-specific promotion decision before promising a new direct API. The existing catalog does not receive blanket accessibility, every-state or every-browser certification from one shared test. Independent onboarding, fresh compatible-native-WebMCP observation, real-provider BYOK proof, commercial pilots and publication approval remain separately recorded gates.
