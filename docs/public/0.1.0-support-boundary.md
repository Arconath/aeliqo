# Aeliqo 0.1.0 support boundary

Aeliqo 0.1.0 supports a pure JavaScript core and runtime, one shared web
component implementation, thin React bindings, local and authenticated HTTP
data paths, local Studio and DevTools, and optional agent integrations through
the documented server-side protocol boundary. Applications continue to own
their data, authenticated principal, routes, and business effects.

The release artifacts contain six public Apache-2.0 packages. They do not need
an Aeliqo account or license service. A model is optional: direct components,
typed tasks, local evaluation, interactions, and presentation work without one.
Provider credentials belong only in a trusted host process and are never a
browser configuration value.

Basic local audit export is included in the runtime package. It retains only
the documented low-cardinality event shapes under explicit memory budgets and
does not store, transmit, search, or centrally operate audit history. Hosts must
scope each collector and map source-specific failures to stable codes rather
than passing records, prompts, credentials, URLs, or user identifiers.

The supported UI matrix is the one recorded by the release evidence. Automated
keyboard, browser, narrow layout, large-text, RTL, forced-color, SSR, hydration,
and accessibility checks do not amount to universal WCAG certification or
manual assistive-technology certification. Native mobile and desktop renderers
are not part of 0.1.0. Native WebMCP remains experimental and is advertised only
when the actual host exposes the negotiated API.

Performance figures apply to the named hardware, fixtures, browsers, and bundle
entries in the evidence. They are not universal pixel, latency, or row-count
guarantees. Unsupported queries, meanings, grants, and provider behavior return
typed outcomes; they are not converted into fabricated success.

The clean `@aeliqo/sdk-*` package family is an incompatible lineage reset, not
an automatic upgrade from historical 0.2 package names. Consumers should pin
the exact version and follow the [migration guide](../migration-0.1.0.md).
Public registry availability, source release availability, and the production
website are verified independently during release.
