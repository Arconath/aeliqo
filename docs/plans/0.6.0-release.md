# Aeliqo 0.6.0 implementation and acceptance

Status: implementation integrated; visual-audit corrections and final release qualification in progress. Source metadata and the five public package manifests target **0.6.0**; the registry has not been promoted to this version. This record supersedes the hosted Playground relay proposal. Historical release receipts remain unchanged.

## Product contract

Applications register data, authority, actions, components and layouts. Aeliqo adapts those registrations to intent and available container space. The application retains identity, routes and business effects. Manual and agent requests use the same validation, runtime and rendering contracts.

- Public Playground: manual controls and native WebMCP only. Remove hosted relay, local MCP selectors and in-page model prompts.
- MCP and BYOK remain public SDK capabilities, demonstrated by a standalone, cloneable local example. Credentials stay in the trusted server process.
- Adaptation covers components, multi-result workspaces and host-registered whole-page layouts, including registered header/sidebar views.
- Documentation has Get started, Components and Advanced navigation, complete runnable steps and accurate version facts.
- All 71 catalog components, including 2D visualizations, require substantive documentation and visual/behavioral review.
- Publish five public packages at 0.6.0, then the verified immutable site image through the existing production GitOps path.

## Required implementation details

### Documentation

Get started explains the product, renders a first example, connects owned data and adds an agent. Components provides a searchable family catalog. Advanced contains composition/state, remote data/permissions, custom views, protocols/models, SSR, performance, API and migrations. Keep existing canonical paths and redirect combined pages. Header/footer brand links go to https://aeliqo.com/; Docs goes to https://docs.aeliqo.com/; internal docs links stay on the docs origin.

Every tutorial provides a concrete outcome, prerequisites, exact commands/files, complete sequential code, brief reasons, expected visible results, common recovery steps and one useful next step. Use plain English; introduce terminology only when needed. React is the initial quickstart with tested Vanilla/Vue choices and an explicit Next SSR path. Examples use public exports and are built and mounted from candidate packages.

Each component page retains accurate generated API facts and explains when to use/avoid it, imports, a runnable example, defaults/events, errors/states, keyboard/focus, responsiveness and actual performance limits. Do not replace substantive guidance with generic filler. Keep canonical package guides under docs/packages.

### Adaptation and developer experience

Extend the existing app facade with host-owned pattern/state-mapping registration and make every result descriptor available to recipes while retaining the primary result. Reuse the current resolver/validator/renderer. Overview, list/detail and comparison layouts preserve child identity, eligible state and focus. Dirty exits follow Save/Discard/Stay. Failure retains the last authorized result; forced revocation fences old work. Resize changes presentation, never authorization or model calls.

Prove content/island, consumer catalog, enterprise workspace and editor/job use cases. Preserve bounded rendering, pagination, virtualization, lazy activation, cancellation and disposal. Publish only measured capacity claims.

### Visual quality

Use coherent source tokens and preserve public customization compatibility. Select chevrons remain singular, centered, RTL-aware and separated from text. Check labels/helper/error spacing, focus, long text, disabled/invalid/pending/readonly, forced colors and 44px touch targets even with compact density on coarse pointers. Native popup presentation may differ by platform.

Review site/docs/Playground at 360/768/1440px, 320px reflow and 200%/400% zoom. Check 240/320/480px component containers inside desktop layouts. Avoid document overflow; preserve intentional accessible data scrolling. Review 2D labels, axes, legends, exact data, missing/negative values, precision, keyboard selection and SVG/Canvas DPR2 parity.

Visual references are tied to an approved source revision and pinned browser/OS/font/fixture inputs. Screenshots stay in ignored artifacts. Compare candidate against independently reproduced approved references; never auto-approve a failing candidate. Retain semantic/a11y/geometric tests alongside pixels.

### Agent surfaces

Public Playground exposes Enable WebMCP, sample prompts to copy, manual actions and progressive inspection. Distinguish API available, tools registered, invocation active and rendered success. Shared component/workspace/page sessions must not silently disconnect agents. Reset/disposal abort work and unregister tools. Native, simulated and unavailable evidence remain separate. Use document.modelContext and AbortSignal; preserve supported native compatibility. Origin-trial enrollment is optional when a valid maintainer token is available; explicitly documented supported browser flags remain a qualified experimental path.

Move local host ownership into examples/local-agent. It supplies a small Vanilla/Vite UI, Node host, MCP HTTP/stdio, optional bounded model loop and .env.example. Its install/start path must work outside this workspace using pinned published packages, without workspace dependencies or source-relative imports. Keep credentials in .env.local/server only. Default startup makes no paid requests. Provider independence is implemented through ToolModelPort and protocol adapters, without claiming every provider's wire format is identical.
