# POC validation

Verified locally on 2026-09-05 using Node 24.20.0, pnpm 10.30.3 and Playwright Chromium. These are local observations, not production performance guarantees.

## Fresh checks

`pnpm check` passed: strict TypeScript, ESLint, package dependency boundaries, 26 unit/integration tests, Vite production build, three production-browser tests, and the core performance benchmark.

- Core: 11 tests cover contracts, aggregation, missing-value ordering, atomic rejection, revisions, structural sharing, selective notifications, removal, dataset reconfiguration and binding validity/cycles.
- React: six tests cover selection propagation, compound composition, Ranking/Table switching, stable blocks, subscription cleanup and Trend aggregation.
- MCP: nine tests cover official SDK tool calls, validation, origin rejection, disconnected/timeout behavior, real WebSocket acknowledgements and browser/core integration.
- Browser: all scenarios A–E exercised. The official SDK Client launches the real stdio server, queries the application dataset, mounts Ranking + Detail with a binding, receives the incremented revision, and selects a branch in the production UI. A stale patch is rejected without removing the preserved metric.
- Browser render assertions: retained metric does not rerender during investigation mounting or selection; Comparison does not rerender on selection; Ranking does not rerender when the metric title changes.
- Keyboard checks: scenario tabs support arrows; Enter selects a ranking row. Explorer Table selection updates Detail.
- Desktop (1440px) and mobile (390px) screenshots inspected. Mobile has no page overflow; compact Ranking hides bars while preserving semantic labels and values.
- Automated axe WCAG 2 A/AA and 2.1 AA checks report zero violations in the overview and investigation. This is not a comprehensive accessibility certification.

## Measurements

Core benchmark: 50 mounted nodes, 100 warm-up patches and 1,000 measured single-node configuration patches. Observed p50 0.0045 ms, p95 0.0092 ms, maximum 0.1453 ms. Across all 1,100 patches, the targeted subscriber received 1,100 notifications and unrelated subscribers received zero. This benchmark excludes React/DOM/network work.

Production browser screenshot records a 0.20 ms synchronous investigation patch on the 12-branch fixture. It excludes browser paint and is one local observation. Interaction and render-isolation assertions run against the production build, not React development timing.

Production assets (gzip): entry JavaScript 79.07 kB, asynchronous MCP browser adapter 13.63 kB, CSS 3.40 kB. The adapter is fetched after mounting. `dist/bundle-report.json` records React, modular D3 dependencies and Zod; the build rejects accidental inclusion of MCP SDK/server modules in the browser. No monolithic D3, model SDK, Canvas or worker runtime is used.

## Evidence and limits

`test-results/investigation-desktop.png`, `investigation-mobile.png` and `mcp-live-browser.png` are regenerated by browser tests. Tests verify unsubscription and connection cleanup; no known subscription leak remains. Acknowledgement confirms browser-core application, not completed paint. This is a single-browser local bridge with a small fixture, not a production authentication or large-data scalability claim. An actual Codex client can use the README launch configuration; the automated proof uses the official SDK client rather than installing an MCP connection into the user's Codex settings.
